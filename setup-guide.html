Put your bank sheets online, safely

The website is written and uploaded. Your two Excel files will live in your private Google Drive, and the page reads them only after you sign in with Google.

5 stepsEach one ends with a way to check it worked.
about 30 minutesNo router, no certificates, nothing to install on the NAS.
FreeGoogle Drive, Google Cloud and GitHub Pages all have free tiers that cover this.

What you are building

You open a web page and sign in with Google. Google checks that it is really you and gives the page a short-lived, read-only pass to your Drive. The page downloads the two spreadsheets, shows them as tables, and forgets everything when you close it.

Web pageHosted on GitHub Pages. Contains no data, only code.
Google sign-inProves who you are and issues a one-hour read-only pass.
Your DriveHolds the two Excel files. Private to your account.

There is no server of your own to run or to attack. The only parts that matter for safety are your Google account, your GitHub account and the Drive sharing setting. Step 1 and the "How it is protected" section cover all three.

Have these ready

  • The Google account theerat.pp@gmail.com, its password and your phone.
  • Your GitHub login for theeratpj-code and your phone.
  • The two Excel files, My Smart Bank transaction 2025 OK.xlsx and My Smart Bank transaction 2026.xlsx, on this Mac or reachable from your NAS.

1

Lock down your accounts

With no server involved, these two accounts are the whole security of the project. Do this before anything else.

About 10 minutes

  1. Delete the leaked GitHub token

    You pasted a GitHub token into the chat. Go to github.com/settings/tokens, open the token that starts with ghp_, press the red Delete button and confirm. Check both the "Fine-grained" and "Tokens (classic)" lists.

    You should seeNo token left in either list.

  2. Turn on 2-Step Verification for GitHub

    Go to github.com/settings/security and, under Two-factor authentication, click Enable. A passkey or an authenticator app is stronger than text messages.

    Whoever can log in to your GitHub can change the website's code. That is the single most valuable thing an attacker could take over here, so this task matters most.

  3. Turn on 2-Step Verification for Google

    Go to myaccount.google.com for theerat.pp@gmail.com and make sure 2-Step Verification is On. Add a passkey if you can.

    Also open the Security Checkup, sign out of devices you do not recognise, and keep your recovery phone and email current.

  4. Use a password that exists nowhere else

    Both accounts need long passwords that you use for nothing else. A password manager (for example the one built into your browser or Apple's Passwords app) makes that painless.

2

Put the files in Google Drive

The page can only read what is in your Drive, and only after you sign in. Keep the files private, then note each file's ID.

About 10 minutes

  1. Upload the two Excel files

    Open drive.google.com as theerat.pp@gmail.com. Click New then New folder and name it My Smart Latex. Open the folder and drag both Excel files into it.

    Files on the NAS?Download them from File Station to your Mac first (right-click, then Download). Later you can automate this with the Synology "Cloud Sync" package; see the note at the end of step 5.

  2. Make sure nothing is shared

    Right-click each file, choose Share, and look at General access. It must say Restricted, and the only person listed must be you.

    Never use "Anyone with the link"That would let any person with the link read your bank data, no sign-in needed.

  3. Copy the ID of the 2025 file

    Double-click the 2025 file to open its preview, then look at the address bar. It looks like this:

    https://drive.google.com/file/d/1AbCdEfGhIjKlMnOpQrStUvWxYz/view

    The highlighted part between /d/ and /view is the file ID. Copy it into a note and label it "2025".

  4. Copy the ID of the 2026 file

    Do the same for the 2026 file and label it "2026". Keep both IDs for step 4.

    A file ID is not a secretOn its own it opens nothing. Google still checks who you are and refuses anyone but you.
3

Set up the Google sign-in

This gives the website a Client ID, a public name tag that tells Google which website is asking. It also limits who can ever sign in to this app.

About 10 minutes

  1. Create a project

    Open console.cloud.google.com as theerat.pp@gmail.com and accept the terms if asked. Click the project name at the top left, then New project. Name it My Smart Latex, click Create, and make sure it is the selected project.

  2. Turn on the Google Drive API

    Click the menu icon (three lines), then APIs & Services then Library. Search for Google Drive API, open it and click Enable.

    You should seeA dashboard for "Google Drive API" with a green status.

  3. Set up the consent screen

    Open APIs & Services then OAuth consent screen (Google also calls this "Google Auth Platform") and click Get started.

    1. App information: name My Smart Latex, support email theerat.pp@gmail.com. Click Next.
    2. Audience: choose External. Click Next.
    3. Contact information: your email. Click Next.
    4. Finish: tick the agreement, click Continue, then Create.

  4. Allow only yourself

    In the left menu click Audience. Make sure the publishing status says Testing. Under Test users click Add users, type theerat.pp@gmail.com and click Save.

    Do not press "Publish app"In Testing mode, Google itself refuses every account that is not on this list. Publishing would open the sign-in screen to everyone.

  5. Choose the read-only permission

    In the left menu click Data Access, then Add or remove scopes. Find .../auth/drive.readonly ("See and download all your Google Drive files"), tick it, and click Update then Save.

    Read-only means the page can never change or delete anything in your Drive.

  6. Create the Client ID

    In the left menu click Clients, then Create client. Set Application type to Web application and the name to My Smart Latex web.

    Under Authorized JavaScript origins click Add URI and paste exactly:

    https://theeratpj-code.github.io
    No slash and no page nameDo not add / or /MySmartLatex. Leave "Authorized redirect URIs" empty. Click Create.

  7. Copy the Client ID

    A window shows a long Client ID ending in .apps.googleusercontent.com. Copy it into your note. You do not need the "Client secret" and should never paste it anywhere.

4

Publish the website

You will fill in the three blanks in the settings file and switch on GitHub Pages. Both are done in your browser.

About 5 minutes plus a short wait

  1. Open the settings file

    Go to config.js on GitHub, sign in, and click the pencil icon at the top right of the file.

  2. Fill in the three values

    Replace the three PASTE_ values with your Client ID and the two file IDs from your note. Leave everything else as it is.

    window.APP_CONFIG = {
  GOOGLE_CLIENT_ID: "YOUR-CLIENT-ID.apps.googleusercontent.com",
  LOGIN_HINT: "theerat.pp@gmail.com",
  IDLE_MINUTES: 15,
  FILES: [
    { label: "2025", id: "FILE-ID-2025" },
    { label: "2026", id: "FILE-ID-2026" },
  ],
};

  3. Save the change

    Click the green Commit changes... button, keep Commit directly to the main branch selected, and click Commit changes again.

  4. Turn on GitHub Pages

    Open the repository's Pages settings. Under Build and deployment set Source to Deploy from a branch, pick branch main and folder /docs, and click Save.

    Pages greyed out?Free GitHub plans publish Pages only from public repositories. That is fine here: the repository holds code only, with no bank data. Change it under Settings, then General, at the bottom.

  5. Wait for it to go live

    Refresh the Pages settings after a minute or two.

    You should seeA banner: "Your site is live at https://theeratpj-code.github.io/MySmartLatex/".

  6. Protect the code from accidental or hostile edits

    In the repository open Settings then Rules then Rulesets and click New ruleset, New branch ruleset. Name it protect main, set Enforcement to Active, add the target Default branch, and tick Restrict deletions and Block force pushes. Click Create.

    Together with 2-Step Verification (task 1.2) this makes it much harder for anyone to slip in code that steals your Google pass.

5

Test it

One run-through to confirm every link works and the permissions look right.

About 5 minutes

  1. Open the site

    Visit theeratpj-code.github.io/MySmartLatex.

    You should see"Bank transactions" and a Sign in with Google button.

  2. Sign in and read the permission screen

    Click the button and choose theerat.pp@gmail.com. Google may say it has not verified the app. That is expected in Testing mode; click Advanced and then Go to My Smart Latex.

    Read the next screen before you click Continue. It must ask only to "See and download all your Google Drive files". If it offers anything that says edit, create or delete, stop and go back to task 3.5.

  3. Read your data

    A table should appear. Switch between 2025 and 2026, pick a sheet, and type in the filter box.

    You should seeRows from your Excel files and a count such as "120 of 120 rows".

  4. Sign out and check access is gone

    Click Sign out. The table disappears and the page withdraws its Drive pass. Reload the page: you are asked to sign in again.

  5. Check from a private window

    Open the address in a private or incognito window on another device. You should see only the sign-in button and no data, even though the website is public.

Finished

Your bank sheets are readable only after a Google sign-in, and only by you. When you replace a file in Drive with a new version, the site shows the new rows the next time you open it.

S

How it is protected

No system can promise to be unhackable, and anyone who says so is wrong. This setup removes the usual weak points and leaves a short list of things you control.

What is built in

  • No server of yours. Nothing is open to the internet except a static page, so there is no login form, database or open port to attack.
  • The data never touches GitHub. The repository holds code only, and Excel files are on the ignore list.
  • Google does the checking. Only your account can authorise the app (Testing mode), and the files are private in Drive, so Google refuses everyone else.
  • Read-only pass. The page can only read. It cannot edit or delete anything.
  • Short life. The pass lasts about an hour, is held in memory only (never saved to the browser), is withdrawn at sign-out, and the page signs you out after 15 idle minutes.
  • Strict page rules. A content security policy lets the page talk only to Google and itself, and blocks inline scripts. The spreadsheet library is stored with the site rather than loaded from a third party.
  • Safe display. Spreadsheet cells are shown as plain text, so a booby-trapped cell cannot run code. Only files owned by your account are opened.

If something goes wrong

Find the message you see and follow the fix.

The page says "This site is not set up yet"

A PASTE_ value is still in config.js, or an ID has a typo or a space. Redo task 4.2 and wait a minute for GitHub to update.

The Sign in button is greyed out

Google's sign-in script has not loaded. Check your internet connection and that no ad blocker is blocking accounts.google.com, then reload.

Google says "Error 400: origin_mismatch" or "invalid_client"

The origin in task 3.6 must be exactly https://theeratpj-code.github.io with no slash and no page name, and the Client ID in config.js must be the one from the same project. Changes can take a few minutes to apply.

Google says "Access blocked: has not completed the verification process"

Your email is not on the test user list. Repeat task 3.4 and add theerat.pp@gmail.com.

The page says "Google refused access"

The Drive API is probably not enabled (task 3.2) or you approved the sign-in without the Drive permission. Click Sign out, then sign in again and allow the Drive permission.

The page says "File not found in Drive"

A file ID in config.js is wrong, or you signed in with a different Google account from the one that owns the files. Redo tasks 2.3, 2.4 and 4.2.

The page says the file "is not owned by your Google account"

The page deliberately refuses files that someone else owns. Upload your own copy to your Drive (task 2.1) and use that file's ID.

The page says "not an Excel or Google Sheets file"

The ID points at a different kind of file (for example a PDF or a folder). Open the correct Excel file and copy its ID again.

I changed the file in Drive but the page shows old rows

Click Sign out and sign in again, or reload the page. The page downloads the file fresh each time and keeps nothing.

A

Plain-English glossary

Client ID
A public label that tells Google which website is asking for a login. It is not a password.
File ID
The code in a Drive file's address that identifies the file. It opens nothing for people Google has not approved.
Testing mode
A Google setting where only people on your test list can sign in to your app.
Read-only permission
A pass that lets the page look at files and download them, but never change or delete them.
2-Step Verification
A second proof, such as a code or a phone prompt, needed in addition to your password.
Content security policy
A rule list built into the page that tells the browser which other sites the page may contact.
GitHub Pages
GitHub's free service that publishes a folder of files as a website.
Your progress is stored in this browser only. Clear your browser data and the ticks reset.
